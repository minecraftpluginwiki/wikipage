# CoreProtect (コアプロテクト)

**CoreProtect** は、Minecraft（Spigot / Paper / Purpur）サーバーにおいて、プレイヤーのあらゆる行動履歴を高速かつ軽量に記録するデファクトスタンダードの荒らし対策プラグインです。  
ブロックの設置・破壊はもちろん、チェストからのアイテムの出し入れ、点火・爆発、ドアの開閉、チャットやコマンドの履歴まで詳細にロギングします。万が一サーバーが荒らされたり誤って建築が壊された場合でも、数秒でピンポイントまたは範囲指定でのロールバック（巻き戻し）が可能です。

:::warning

**編集時点**での情報を元にしています。
今後のバージョンアップで仕様変更が行われる可能性があります。

:::

## 導入手順

1. **サーバーを停止する**  
   コンソールで `stop` を実行し、サーバーを完全に停止します。

2. **jar ファイルをダウンロードする**  
   サーバーの Minecraft バージョンに対応した `CoreProtect-x.x.x.jar` をダウンロードします。

3. **plugins フォルダへ配置する**  
   ダウンロードした `.jar` ファイルをサーバーの `plugins/` フォルダに入れます。

4. **サーバーを起動する**  
   サーバーを起動すると、`plugins/CoreProtect/` ディレクトリと設定ファイル（`config.yml`）、および標準の SQLite データベースが自動生成されます。

5. **導入確認**  
   ゲーム内またはコンソールで `/co status` を実行し、プラグインのバージョンやデータベースの接続状態が正常であれば完了です。

## 主なコマンド一覧

:::tip
`/coreprotect` コマンドは、すべて短縮形の **`/co`** で実行できます。
:::

### 基本コマンド
| コマンド | 説明 |
| :--- | :--- |
| `/co inspect` (または `/co i`) | 調査（インスペクト）モードの ON/OFF を切り替えます。 |
| `/co rollback <パラメータ>` (または `/co rb`) | 指定した条件のブロックやチェストを過去の状態に巻き戻します。 |
| `/co restore <パラメータ>` (または `/co rs`) | 直前のロールバックを取り消し、元に戻します。 |
| `/co lookup <パラメータ>` (または `/co l`) | 条件に一致するログをチャット欄に検索・表示します。 |
| `/co purge <時間>` | 指定した期間より前の古いログデータをデータベースから削除します。 |
| `/co reload` | 設定ファイル（`config.yml`）を再読み込みします。 |
| `/co status` | データベースの接続状況や保留中のキュー数を確認します。 |

## ロールバック・ログ検索のパラメータ指定方法

`/co rb` や `/co l` の後ろにスペース区切りで指定するパラメータです。

| パラメータ | 記述形式 | 指定例 | 説明 |
| :--- | :--- | :--- | :--- |
| **プレイヤー** | `u:<名前>` | `u:Steve` / `u:#creeper` | 対象プレイヤー（モブ・爆発は `#` プレフィックス） |
| **時間** | `t:<数値><単位>` | `t:30m` / `t:2h` / `t:7d` | 遡る期間（`s`:秒, `m`:分, `h`:時間, `d`:日, `w`:週） |
| **半径** | `r:<数値>` | `r:15` / `r:#world` | 自分の現在地からの半径（`#world` でワールド全体） |
| **アクション** | `a:<アクション>` | `a:+block` / `a:-block` | `+block`:設置, `-block`:破壊, `container`:チェスト操作 |
| **ブロック** | `b:<ブロックID>` | `b:tnt` / `b:diamond_block` | 対象とする特定のブロック/アイテム |
| **除外** | `e:<ブロックID>` | `e:stone` / `e:dirt` | ロールバック対象から除外したいブロック |

## 実践：よく使うロールバックのコマンド例

### 1. 調査モード（インスペクト）を使う
`/co i` を実行してインスペクトモードを有効にした後、ブロックを操作します。
- **左クリック**: そのブロックを「誰が」「いつ」壊したかを確認
- **右クリック**: 隣接する空間に「誰が」「いつ」ブロックを置いたかを確認
- **チェストを右クリック**: チェストから「誰が何個のアイテムを出し入れしたか」を確認

### 2. シーン別ロールバック具体例

```text title="よく使うコマンド集" showLineNumbers {2,5,8,11}
# 例1: 悪質プレイヤー "bad_guy" が過去2時間に行った破壊・設置をすべて巻き戻す
/co rb u:bad_guy t:2h r:#world

# 例2: 自分の周囲 半径 20 ブロック以内で、過去 30 分間に起きたクリーパー爆発を修復する
/co rb u:#creeper t:30m r:20

# 例3: 過去 1 時間以内にチェストから盗まれたダイヤと金インゴットを元に戻す
/co rb t:1h r:10 a:container b:diamond,gold_ingot

# 例4: ロールバックに失敗したため、直前のロールバックを取り消して元に戻す
/co rs t:1h r:20
```

coreprotect.lookup

## config.yml の日本語訳・おすすめ設定

設定ファイル（`plugins/CoreProtect/config.yml`）内の重要項目です。

```yaml title="plugins/CoreProtect/config.yml" showLineNumbers {3,8,13-17,23-28}
# ----------------------------------------------------
# 1. 調査モード（/co i）の初期ツール
# ----------------------------------------------------
# デフォルトで手ぶら（素手）でクリックしても調査可能にするか
inspect-blocks: true

# ----------------------------------------------------
# 2. ロギング（記録）対象の設定
# ----------------------------------------------------
# チェストや樽のアイテム出し入れを記録する（必須推奨）
item-transactions: true

# ドアやレバー、ボタンの操作ログを記録するか（ログ肥大化を防ぐなら false）
player-interactions: false

# チャットやコマンドの実行ログを記録するか
player-chat: true
player-commands: true

# ----------------------------------------------------
# 3. データベース接続（中・大規模サーバー向け）
# ----------------------------------------------------
# サーバー規模が大きくなる場合は MySQL / MariaDB への接続を推奨
use-mysql: false
table-prefix: 'co_'
mysql-host: '127.0.0.1'
mysql-port: 3306
mysql-database: 'minecraft'
mysql-username: 'root'
mysql-password: 'your_password'
```

## データベースの運用と肥大化対策 (Tips)

CoreProtect は初期設定で **SQLite**（ファイル保存）を使用しますが、長期間サーバーを運用するとログデータが数十GBに膨れ上がり、サーバー起動やロールバックが遅くなる原因になります。

:::tip 
データベースのメンテナンス方法

1. **古いログの定期削除（Purge）**  
   サーバーコンソールまたはゲーム内で `/co purge 30d` を実行すると、30日以上前の古いログを一括消去してデータベースの容量を圧縮できます。
2. **中・大規模サーバーでは MySQL / MariaDB を使用**  
   同時接続数が10人を超える場合は、`config.yml` の `use-mysql: true` を設定し、外部データベースにログを任せることでサーバー本体の負荷を大幅に軽減できます。
:::

## よくある質問・トラブルシューティング (FAQ)

### Q1. ロールバックしても水や溶岩などの液体が戻りません
**解決策**: 液体は標準のブロック復元と判定が異なる場合があります。パラメータに `a:+block` やブロック指定を外して範囲で指定し直すか、WorldEdit の `//fixwater` などを併用してください。

### Q2. `/co purge` を実行しても `.db` ファイルの容量が小さくなりません
**原因**: SQLite の仕様上、行を削除しても空き領域がファイル内に予約されたまま残ります。  
**解決策**: サーバーを停止させた状態で SQLite の `VACUUM` コマンドを実行するか、定期的に MySQL / MariaDB へ移行して運用することをおすすめします。

### Q3. ロールバックを実行中にサーバーが重くなります
**解決策**: 一度に広すぎる範囲（例: 半径500ブロック以上、期間1ヶ月など）を指定すると、データベースからの読み込みに時間がかかります。半径 `r:50` 程度に絞るか、プレイヤー名 `u:<名前>` を必ず指定してクエリの検索対象を絞り込んでください。
